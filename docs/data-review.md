# OrthoLab 資料審閱紀錄

來源檔：`data-source/veterinary-ortho-game-source.xlsx`（附件《獸醫骨科小遊戲 (1).xlsx》），以 `npm run data:extract` 轉成 `src/data/generated/source.json`。所有原始 ID 與來源關係都保留；修正一律在 `src/data/mapping.ts`、`src/data/index.ts`、`src/config/tolerances.ts` 中以覆寫方式進行，原值仍可追溯。

本文件記錄：發現的問題、本版處理方式、仍待專科審閱的項目。

## 1. 讀取與型別轉換

| 項目 | 處理 |

| 10 張工作表 | 全部讀取（疾病庫、病例庫、檢查線索庫、處置判定表、術式與步驟表、術後與資源表、術式模組、參考資料、骨折微調與數值容差表、美術風格與圖片規範表）。 |
| 尾端空白列欄 | 多數表格標示 1000 列 × 26 欄，實際資料遠少；空白列與無標題欄已移除。 |

## 2. ID 衝突（T05／T06）

原始「處置ID」一欄同時代表處置技術、模組與選項：

- **T05**：術式模組表定義為「關節囊外固定」，但 A30（副木）、A35（外夾板／包紮）也用 T05。
- **T06**：術式模組表定義為「TTA」，但 A31（單獨髓內釘）、A34（髓內釘＋環扎）也用 T06。

處理：建立三層唯一 ID（`src/data/mapping.ts`）

1. 選項：判定ID（A01…）不變。
2. 處置技術：`TX-*`，例如 `TX-ECS`、`TX-TTA`、`TX-EXTERNAL-COAPTATION`、`TX-IM-PIN-ONLY`、`TX-IM-PIN-CERCLAGE`。
3. 模組：`PROC-*`，例如 `PROC-ECS`、`PROC-TTA`、`PROC-ORIF-PLATE`。原始 T 編號只在「術式模組」表語境下對應到模組。

每個選項保留 `rawProcedureId`。骨折副木選項不連到囊外固定畫面（e2e 與單元測試驗證）。

## 3. A34：髓內釘＋鋼線環扎

- 原始：C08「可接受替代」，8 分；必要條件「斜折線長度需大於骨幹直徑 2 倍」。
- 矛盾：C08-E3 描述為「短斜骨折」。本遊戲 C08 幾何模型的折線長度也小於 2 倍骨幹直徑（有測試）。
- 處理：類別改為「條件不足」，分數 `null`（不計分），列出缺少的資訊並標示「待審閱」。原始類別與分數保留在 `sourceCategory`／`sourceScore`。
- **待審閱**：此替代方案在本例是否成立，需骨科專科確認。

## 4. 未經支持的數字與通用規則

| 原文 | 位置 | 處理 |
|---|---|---|
| 單獨外副木固定之不癒合率高達 70~80% | C07-E4、D09 | 遊戲中不顯示該數字，改為定性敘述並加「待審閱」標記。 |
| 每側至少咬合 6 骨皮質 | D09、A33、T09-S4、TOL-04 | 只作為「本關遊戲幾何門檻」，不顯示為通用臨床規則。 |
| 2.0/2.7/3.5 mm LCP 依體重選定 | D09、A29、A33 | 骨板尺寸只作為「本病例資料設定」，不作為選配規則；器械盤中替代骨板只改孔數，不暗示尺寸規則。 |
| 骨板跨距 ≥75% 骨幹長度 | T09-S3、TOL-03 | 遊戲幾何門檻，非通用跨距規則。 |
| 間隙 >1.5 mm（骨不癒合風險） | TOL-02 | 不顯示「骨不癒合風險」；位移誤差改名為「復位位移誤差（遊戲量測）」，不稱臨床間隙。 |
| 穿入關節 → 「關節軟骨損傷與創傷性關節炎併發症」 | TOL-06 | 改為風險提示與修正方式，不宣告病患已發生併發症；依原表扣 20 分一次。 |
| P06 時程（6–8 週、48hr、第 4、8 週） | 術後與資源表 | 保留但標示「原始資料提案，待專科審閱，需依個體調整」。 |

## 5. 容差衝突與區間補齊（單一設定檔 `src/config/tolerances.ts`）

- **角度**：術式表／模組表寫 ≤3°，容差表寫 Pass ≤5°、Perfect ≤2°。依需求以容差表為準（覆蓋紀錄在 `CONFLICT_LOG`）。
- **未定義的中間區段**一律設為「需調整」：
  - 位移 1.0–1.5 mm
  - 跨距 70–75%
  - 安全距 4–5 mm
  - 關節面 0–3 mm（穿透＝未達標）
- **皮質數完美 ≥8**：與「螺釘增加不代表較好」衝突；完美改依「本病例預設構型完成度」。
- 每個設定的區間都覆蓋整條實數線、彼此不重疊（有密集取樣測試），不會有判分空洞。
- 位移的軸向與側向分開計算，兩者都套用 TOL-02（遊戲假設）。
- 所有門檻在 UI 中標示「遊戲幾何門檻，非臨床標準」；不由角度、間隙、螺釘數或距離推論必然骨不癒合或其他併發症。

## 6. 「第一版」不等於可玩

| 項目 | 狀態 |
|---|---|
| D03 CHD、D05 髖脫位、D06 ED、D07 OCD、D10 貓 SCFE | 無病例、線索與操作資料 → 只在知識庫，標示「本版無可玩病例」。D10 標示第一版但完全沒有病例。 |
| T05 囊外固定、T06 TTA | 原始「待補／待專科定義」→ 只提供決策解說，不提供操作畫面。 |
| T07 THR | 只顯示轉介路線。 |
| T08 只加深滑車溝 | T03 的元件，非獨立模組。 |
| T10 麻醉事件 | 未實作；手術中只顯示固定的「模擬監測：穩定」，不產生隨機事件，計時只作提示。 |
| T01-S2 | 原始寫「目前未設定可用數值容差，禁止上線判分」→ 只檢核完成，不計分。 |

## 7. 參考來源

- R13（AO 網站首頁）、R14（BSAVA Library 首頁）只指向出版社／學會首頁：標示「章節／頁碼待確認」，未逐項驗證其支持的數字。
- R12 原始資料未列作者；以 PMID 為準，作者待補。
- R00 為原始需求檔的私人連結，標為「原始需求資料（非醫療證據）」。
- G01 為遊戲設計假設，不是醫療證據。
- 證據類型分為：系統性回顧、臨床指引、專著、學會衛教、大學衛教、敘述性回顧、遊戲設計假設。

## 8. 素材

- C01–C08 X 光與 T09 骨骼／植入物圖層在原始表為「待製作／待補」。本版以原創向量繪製**教學示意**（高對比灰階、患側側標、投照方向、以模型比例繪製的 10 mm 標尺），明確標示「非臨床影像、非 DICOM」。
- 未登錄的影像 ID 會顯示「影像素材待製作」文字卡，不會破圖。

## 9. 遊戲設計假設（G01，可調整）

- 檢查分：每次在必做線索完成前作答 −10，最低 50。
- 推理分：首次「計分」作答的處置分 ×10；條件不足（null）選項不成為計分作答。
- T09 等級折算：Perfect 100%、Pass 80%。
- C07「背內側成角 18°」拆為 Lat 背側 14°、AP 內側 11°（√(14²+11²)≈17.8°）；C08 Lat 平面 1.5 mm 平移為遊戲設定，讓兩個視角都需檢核。
- T09 模型尺寸（骨長、骨寬、孔距、螺釘長度選項）為遊戲模型設定，不是解剖量測或植入物規格。
- T01／T02／T03 的目標標記（截骨標記、切除示意區、滑車溝示意深度、粗隆對齊範圍）為示意圖預設值，不代表臨床數值。
- 照護卡與非手術卡片內容取自 P01–P06、A17–A24、D08 等原始列；不新增藥物劑量、發生率或保證預後。

## 10. 仍待補充／待專科審閱

1. A34 是否為本例可接受替代。
2. 「不癒合率 70–80%」、「每側 6 皮質」、骨板尺寸與跨距比的直接文獻支持（R13／R14 的章節頁碼）。
3. T09 容差數值本身（原表為設計提案）。
4. T01 截骨與旋轉的精度容差（原始資料禁止判分）。
5. T02 切除區範圍。
6. T03 實際術式依賴與順序。
7. P01–P06 照護內容與時程（原始狀態皆為「待專科審閱」）。
8. 真實或授權的影像素材（目前為向量教學示意）。
9. 麻醉事件資料（T10）。
10. D03、D05–D07、D10 的病例、檢查線索與操作資料。

| 項目 | 位置 | 性質與依據 |

## 13. v1.3 病患插圖與觸診回饋（2026-10-25）

| 項目 | 處理 |
|---|---|
| 患肢與姿勢 | 由病例庫「患側」文字解析（`limbsFromSide`）與既有 `pose` 決定，不寫死病例；與患肢定位答案一致（有單元測試）。患側無法解析時不猜測、不抬肢。 |
| 左右對應 | 插圖為面向觀看者的 3/4 坐姿：**病患左側在畫面右側**，右側肢較深色；肢體群組以 LF／RF／LH／RH 標記，不靠鏡像換標籤。 |
| 抬肢 | `fore-lift` 只抬患側前肢、`hind-lift`／`crouch` 只抬患側後肢；C05（站立警戒）與 C06（雙髖僵硬）不抬肢，C06 兩後肢標為患肢但都負重。 |
| 動畫 | 呼吸、眨眼、抬肢微顫、觸診回縮皆為教學示意，不代表疼痛分級或診斷結果；遊戲「減少動態」或系統 prefers-reduced-motion 時全部停止，改顯示短文字提示。 |
